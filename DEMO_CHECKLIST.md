# Redressa AI - Demo Checklist

Use this guide to ensure a smooth, flawless judging demonstration of the Redressa AI workflow.

## 0. Pre-Flight Checks
- [ ] Ensure `.env.local` contains all valid API keys (`GROQ_API_KEY`, `OCR_SPACE_API_KEY`, plus Supabase variables).
- [ ] Run `npm run build` locally to confirm the app compiles without issues.
- [ ] Verify you have a clean database by checking that the Recent Cases list on the homepage is empty (or only shows cases you intend to showcase).
- [ ] Ensure the latest master branch is pushed to Vercel and the deployment is returning `200 OK` on `/api/health`.

## 1. Preparing the Demo Evidence
The project relies on specific supported fact extraction scenarios for its MVP phase. Included in this repo (`data/demo-evidence`) are:
- `indigo-cancellation-email.txt` (or image equivalent)
- `flipkart-damaged-laptop.jpg` (simulated via text stub or live image)
- *If using the live OCR flow, ensure you have a clean `.jpg` or `.png` screenshot of a Flipkart refund denial ready on your desktop.*

## 2. Running the "Seeded" Demo (Fail-safe path)
If Live APIs are rate-limiting or internet is unstable during the pitch:
1. Navigate to `/new` (New Claim page).
2. Click the subtle **"or use a sample case"** expandable `<details>` element below the Submit button.
3. Click either **IndiGo flight cancellation** or **Flipkart damaged goods**.
4. The form will pre-populate, and the backend will utilize pre-seeded files to prevent upload failures.
5. Click **Submit**.

> [!NOTE] 
> The seeded path is functionally identical in the pipeline execution—it extracts the same facts but avoids external network latency during file uploads.

## 3. Running the Live Demo
If you have a solid connection and want to show end-to-end functionality:
1. Start at the Homepage (`/`). Click "File a New Claim".
2. Select **E-Commerce**.
3. Fill out bare minimums (e.g. "Flipkart").
4. Upload a genuine small `.jpg` screenshot representing a refund dispute.
5. Provide a short description.
6. Click **Submit**.
7. *Talking point while loading (30-40s):* "The system is currently running OCR via OCR.space, decoding the text, and streaming the context directly into Groq for classification and fact extraction."

## 4. Walking Through the Case Output
Once the pipeline drops you onto the Tracker (`/case/[id]`):
- **Agent Activity:** Show the right-hand panel confirming the steps taken (OCR parsing, chunking, retrieval).
- **Extracted Facts:** Emphasize the timeline builder and core entity mapping.
- **Citations:** Click a citation to show bounded context—prove the agent isn't hallucinating; it uses real policy chunks.
- **Outputs:** Show the *Grievance Email Draft* and *Escalation Note* generated by the final Groq call.

## 5. Showing Under the Hood (Debug Mode)
To prove the architecture to technical judges:
1. Append `?debug=1` to the URL of any completed case (e.g. `localhost:3000/case/123-abc?debug=1`).
2. This reveals the **Evidence Debug & Tracing** panel.
3. Show the JSON payload containing OCR extraction events and metadata logs verifying dual-model interaction.

## Legal / Hackathon Disclaimer
Remind judges: *Redressa AI is a guidance workflow designed to assist analysts and consumers in translating messy complaints into structured data aligned against company policies. It generates informational escalation drafts, not formal legal advice.*
